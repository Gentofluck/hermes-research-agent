# T1. Сравнение агентных платформ

Сравнил Hermes Agent, OpenClaw, PicoClaw и свой Jarvis. Для задания нужен агент, который может сам выполнить задачу по расписанию, прочитать источники и прислать результат в Telegram. Jarvis использую для сравнения с системой, где работа строится вокруг задач и обсуждения с пользователем.

Сведения о трёх открытых платформах взяты из документации и репозиториев, проверенных 9 ноября 2026 года. Возможности Jarvis проверены по исходникам: `server/jarvis/`, `server/actions/` и схеме Prisma. Одинаковый эксперимент на всех четырёх платформах не проводился.

## Архитектура

| Критерий | Hermes | OpenClaw | PicoClaw | Jarvis |
|---|---|---|---|---|
| Реализация и установка | Python, готовый Docker-образ или исходники | TypeScript, Node.js, пакет или Docker | Go, готовый бинарник или Docker | TypeScript, Fastify, React, PostgreSQL; требуется установка npm-зависимостей и БД |
| Размещение | VPS, локальная машина; есть удалённые среды выполнения инструментов | Локальная машина или сервер, дополнительные устройства подключаются как узлы | Сервер, ПК и маломощные устройства | Локально или на сервере; веб-интерфейс и API в одном процессе |
| Восстановление после перезапуска | В нашем Compose задан `unless-stopped`; шлюз внутри образа контролирует s6 | Фоновый шлюз устанавливается как служба; в Docker нужен restart policy | Зависит от настройки службы или контейнера | Развёрнут как systemd-сервис; незавершённая генерация при рестарте теряется |
| Подсистемы | Шлюзы, инструменты, навыки, файловая память, история сессий, cron | Шлюз, каналы, инструменты, навыки, память, cron, плагины | Каналы, инструменты, навыки, память, cron | Проекты, задачи, треды, навыки в БД и инструменты; отдельного планировщика нет |

Ресурсные показатели нельзя считать напрямую сопоставимыми: для Hermes здесь указан размер скачанного образа, для PicoClaw — заявления разработчика, а для Jarvis — настроенный предел памяти.

| Показатель и условия | Hermes | OpenClaw | PicoClaw | Jarvis |
|---|---|---|---|---|
| Ресурсы | Выделенный VPS: 1 CPU, 2 ГБ RAM; размер образа по Docker inspect — 4 558 319 042 байта | Для пакетной установки нужен Node.js; расход RAM в этой работе не измерялся | README заявляет запуск на слабом оборудовании и указывает 10–20 МБ RAM для недавних сборок | В описании развёртывания установлен `MemoryMax=650M`; это ограничение сервиса, а не измеренный расход |
| Холодный старт | Не измерен | Не измерен | Заявление разработчика — менее секунды; независимо не проверялось | Не измерен |

Источники: [Hermes Docker](https://hermes-agent.nousresearch.com/docs/user-guide/docker), [установка OpenClaw](https://docs.openclaw.ai/install), [PicoClaw README](https://github.com/sipeed/picoclaw).

## Исследовательские задачи

| Критерий | Hermes | OpenClaw | PicoClaw | Jarvis |
|---|---|---|---|---|
| Поиск и чтение страниц | Веб-инструменты и браузер; провайдеры настраиваются отдельно | Поиск, загрузка страниц и управляемый браузер | Веб-поиск и чтение страниц; для сложной браузерной автоматизации нужны дополнительные инструменты | В текущей конфигурации доступны файловые инструменты, встроенного веб-поиска нет |
| JavaScript и авторизация на сайтах | Возможны через браузер; нужна настройка браузерной среды и сессии | Браузер работает с профилями и сессиями | Один HTTP-запрос не заменяет браузер; возможна интеграция через MCP | Не реализованы |
| Файлы и вычисления | Чтение и изменение файлов, терминал, запуск скриптов | Файлы и выполнение команд; среда зависит от настройки изоляции | Файлы и `exec` с ограничениями | Read, Glob, Grep, Edit, Write; Bash не включён в разрешённые инструменты |
| Документы и медиа | Обработка через инструменты, навыки и внешние сервисы | PDF, изображения, аудио и видео через соответствующие инструменты и провайдеров | Возможности зависят от подключённых инструментов; полноценный пакет обработки документов не проверялся | Можно работать с текстом файлов; отдельного импорта PDF, таблиц и расшифровки нет |
| Расширение | `SKILL.md`, собственные инструменты, MCP | Навыки, плагины, MCP | `SKILL.md`, ClawHub, MCP, собственные Go-инструменты | Навыки хранятся в БД и прикрепляются к задаче; собственные действия подключены через SDK MCP-сервер |
| Параллельная работа | Сессии и делегирование подагентам | Сессии, несколько агентов и подагенты | Сессии и запуск подагентов | Разные проекты обрабатываются независимо; в одной папке одновременно работает один запуск |

Источники: [возможности Hermes](https://github.com/NousResearch/hermes-agent), [инструменты OpenClaw](https://docs.openclaw.ai/tools), [инструменты PicoClaw](https://github.com/sipeed/picoclaw/blob/main/docs/reference/tools_configuration.md).

## Эксплуатация

| Критерий | Hermes | OpenClaw | PicoClaw | Jarvis |
|---|---|---|---|---|
| Модели | Разные облачные провайдеры и локальные модели | Облачные и локальные провайдеры | Несколько провайдеров, Ollama и совместимые API | Только Claude API |
| Память | `USER.md`, `MEMORY.md`, сохранённые сессии и поиск по истории | Markdown-память и поиск по ней | Файлы рабочего каталога и история | Треды и навыки в PostgreSQL; весь тред передаётся при новом запросе |
| Наблюдаемость | Логи шлюза, сессии, сведения о расходе | Журналы шлюза, история сессий, учёт использования моделей | Логи и история; фактический учёт стоимости нужно проверять для выбранного провайдера | В сообщениях сохраняются модель, токены и стоимость; есть предел бюджета на запуск |
| Изоляция | В нашей настройке контейнер без Docker socket и папок других проектов, процесс агента не от root | Инструменты основной сессии работают на хосте, если не настроена песочница; есть политики доступа и согласования | Ограничение рабочим каталогом и фильтр команд; он не анализирует рекурсивно всё, что запускают дочерние скрипты | Файловые инструменты и ограничения systemd; согласование части действий описано в промпте и не заменяет проверку в коде |
| Лицензия и сопровождение | MIT, публичная документация и хаб навыков | MIT, документация, плагины и ClawHub | MIT, документация и установка навыков из ClawHub | Личный проект; отдельный файл LICENSE пока не добавлен, готового публичного каталога навыков нет |

У Hermes, OpenClaw и PicoClaw есть недавние изменения в публичных репозиториях. Это подтверждает активную разработку, но не доказывает стабильность конкретной версии. Для развёртывания Hermes закреплён digest образа.

Источники: [память Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory), [провайдеры OpenClaw](https://docs.openclaw.ai/concepts/model-providers), [память OpenClaw](https://docs.openclaw.ai/concepts/memory), [безопасность OpenClaw](https://docs.openclaw.ai/gateway/security), [настройка PicoClaw](https://github.com/sipeed/picoclaw/blob/main/docs/guides/configuration.md). Лицензии проверены в репозиториях [Hermes](https://github.com/NousResearch/hermes-agent), [OpenClaw](https://github.com/openclaw/openclaw), [PicoClaw](https://github.com/sipeed/picoclaw).

## Выбор

Для выбора задал следующие приоритеты. Веса отражают требования моей задачи, а не результаты измерения качества платформ.

| Критерий | Вес | Почему |
|---|---:|---|
| Автономный запуск и доставка результата | 25% | Дайджест должен выполняться по расписанию без открытого чата |
| Источники, файлы и расширение навыком | 25% | Нужно получить статьи, отобрать их и сохранить результат |
| Ограничение доступа | 20% | Агент имеет терминал и доступ к API |
| Развёртывание и сопровождение | 15% | Нужны постоянные данные, перезапуск и понятные логи |
| Учёт расходов и выбор модели | 15% | Запуски регулярные, стоимость должна быть контролируемой |

Для практической части выбрал Hermes: Telegram, cron и навыки уже встроены, а собственный `paper-digest` можно добавить без изменения платформы. OpenClaw тоже подходит; преимуществ, которые оправдывали бы перенос уже подготовленной конфигурации, для этого задания не нашёл.

PicoClaw рассмотрел бы для устройства с небольшим объёмом памяти, предварительно проверив нужные инструменты на нём. Jarvis удобнее для задач, которые нужно обсуждать и согласовывать в веб-интерфейсе. Для автономного дайджеста ему пришлось бы добавить планировщик, получение источников и канал доставки.
